## Findings

### A. pr-quiz (#1)

- **What.** [pr-quiz](https://github.com/dkamm/pr-quiz) is a GitHub Action that uses AI to
  generate a quiz from a pull request. The GitHub API on 2026-11-27 reports 211 stars, created
  2025-06-19, last push 2025-11-24. Promo post
  [JohnDoritosKane](https://x.com/JohnDoritosKane/status/2112490958059348400), 0 likes.
- **Adds.** A shipped action that quizzes on the pull request itself. The brief does not say it
  blocks merge or push.
- **Evidence:** `practitioner`. Stars are the signal.
- **Use.** #1, as a source next to Litt's quiz and codebase-to-course. Not a merge gate for
  human-review.

### B. Mironyx PRCC and FCS (#1 and #2)

- **What.** [Mironyx](https://mironyx.dev/product) has a Feature Comprehension Score (FCS) and a
  PR Comprehension Check (PRCC). Write-up
  [Feature Comprehension Score](https://mironyx.dev/blog/feature-comprehension-score) (March
  2026, Leonid Sokolovskiy).
- **Questions.** The product page says an AI generates 3 to 8 comprehension questions from the
  PR diff, description, linked issues, and design docs, with reference answers and weights, and
  that "the rubric is fixed before anyone sees the questions". Questions target Naur's three
  layers ("Programming as Theory Building"): domain mapping, design justification, and
  modification capacity. The example is "What would break if we changed the retry policy from
  exponential to fixed-interval, and which tests would catch it?"
- **Scores.** Participants answer independently. Individual scores are never tracked or
  reported. The unit is the team.
- **When it runs.** PRCC fires when a PR is opened or updated, in a soft or a hard merge-gate
  mode. A web-search summary of their site says hard mode defaults to a 70% threshold. That
  70% is from their site via search, and it was not verified on the page. FCS is
  admin-initiated after a feature.
- **X.** [@leonidmironyx](https://x.com/leonidmironyx/status/2087643997997064363) posts with
  about 0 likes.
- **Evidence:** `vendor`, no engagement.
- **Use.** #1 borrows the three question types. One domain-mapping question, one
  design-justification question, and one modification-capacity question. Check the last against
  the code or the tests. Have the build write the answer key, with `path:line`, before the quiz
  renders, so the key cannot drift to fit the reader. Keep HR's quiz a self-check. A merge gate
  is out of scope for human-review. #2 keeps any shipped quiz scores in the reader's own Copy
  feedback export. Mironyx reports a team-level aggregate only and never individual scores, so
  do not aggregate per person.

### C. Sphinx (#1)

- **What.** Sphinx is a Git hook that quizzes you on your AI agent's code before push and
  blocks the push if you cannot explain it. The only source is a teardown post
  ([DaDw26](https://x.com/DaDw26/status/2117323355032617161), 2026-11-02, 7 likes, 11 replies,
  277 impressions).
- **Evidence:** `practitioner`, low engagement. No repo link found.
- **Use.** #1, as a source for a quiz that can block a push. Not a design to copy. HR's quiz
  stays a self-check.

### D. Bridgekeeper (#1)

- **What.** [Bridgekeeper](https://bridgekeeper.io/) returned HTTP 500 on 2026-11-27. The
  description comes from a search index only. It filters the diff to material changes, asks
  the reviewer to predict the implementation and the rationale before revealing the diff, then
  asks category-specific Socratic questions (index or access pattern, latency, concurrency,
  security boundary, migrations, API breaks). An LLM judge decides whether understanding is
  enough to merge.
- **Evidence:** unverified.
- **Use.** #1, labeled unverified. The predict step is the same direction as the PRIMM
  predict-run already noted on #1. See the PRIMM note in sweep 2026-11-25 (open PR #41, not on
  `main`). Using that judge as a merge gate is out of scope for human-review.

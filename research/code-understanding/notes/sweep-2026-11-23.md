## Findings

### A. diffle 0.5.2 — shipped confirmation, and #6

- **What.** [diffle](https://github.com/moritzwilksch/diffle) 0.5.2, "Take a tour of the change",
  dated Nov 13, 2026 on the [changelog](https://diffle.app/changelog/). A Claude skill
  (`diffle skill > ~/.claude/skills/diffle/SKILL.md`) has the agent write a tour. Press T. The
  tour is one page beside the diff. It explains the change in order, shows the lines it talks
  about, and ends with the questions the reviewer needs to decide. n and p move between sections.
  l and h step through a walk or diagram. Pressing c comments on the selected words, and the
  comment reaches the agent like any other review comment. `diffle comments reply` (0.5.2) lets
  the agent answer in the thread. `diffle comments list` (0.5.0) prints the threads as JSON
  mid-review. Export saves the tour as one HTML file that opens offline.
- **X.** No engagement found. The supplied search for 2026-11-10 through 2026-11-23 returned
  nothing. Not re-counted.
- **Evidence:** `vendor`.
- **Use.** Confirmation, not a new item. The ordered tour, the lines each section talks about,
  and the questions at the end are what human-review already ships (reading order, and "What I
  need from you"). The one offline HTML file is the same shape as the shipped page. #6. The
  comment on selected words, delivered into the agent session, with a threaded reply, is direct
  prior art for "Ask about this" from any line or block, answered in the agent session.

### B. Understand-Anything v2.9.8 — #3 and #11

- **Release.** [v2.9.8](https://github.com/Egonex-AI/Understand-Anything/releases/tag/v2.9.8),
  "Code lessons", published 2026-11-15T12:10:30Z. Understand-Anything is already cited on #3 and
  #7. Code lessons are not.
- **Lessons.** Per-file explanations aligned with the guided tour in the code viewer.
  Tour-covered files get detailed sections. Other files get an overview. Clicking a section
  highlights its source lines. Lessons are generated when the tour is built or rebuilt, published
  after the graph is saved, and pruned when files leave the graph. A partial update preserves
  existing lessons. A tour rebuild refreshes their line ranges. The dashboard and the skills that
  read the graph report when saved analysis is stale.
- **MCP.** The same release adds a stdio MCP server. The highlights name onboarding, explanation,
  and change-impact analysis among its tools, plus status, search, and dashboard startup. Each
  tool includes graph freshness.
- **Evidence:** `vendor` (open-source release notes). No outcome data.
- **Use.** #3, teach-code v2. Stateful lessons that survive code changes: prune when a file leaves
  the graph, re-anchor line ranges on a tour rebuild, and a staleness flag. That is a concrete
  design to copy. #11. A one-line pointer: clicking a section highlights the source lines. A step
  that opens the code.

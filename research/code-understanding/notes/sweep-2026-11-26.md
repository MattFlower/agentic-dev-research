## Findings

### A. Archify — #7, #11, and #12

- **What.** [tt-a1i/archify](https://github.com/tt-a1i/archify), Agent Skill `archify-pr` for
  Claude Code, Codex, and Cursor. The design is
  [pr-review.md](https://github.com/tt-a1i/archify/blob/main/archify/references/pr-review.md).
  GitHub API on 2026-11-26: `stargazers_count` 100316. v3.3.0 released 2026-11-22, per the
  [codebumble write-up](https://codebumble.net/insights/archify-v3-3-agent-skill-interactive-diagrams)
  (third-party).
- **Materiality.** A preflight computes materiality from changed files, changed lines, and path
  classes, and only offers diagrams for a material diff. A small schema or migration change still
  qualifies. That gate is on #12.
- **Propagation.** Views are sliced by how the change propagates. Storage shape (`erd`), then
  boundaries and state (`lifecycle`, `architecture`, `workflow`), then interaction and payloads
  (`sequence`, `dataflow`, with before and after payloads). That order is on #7.
- **One view.** Each view is one merged superset of before and after. Elements are marked added,
  modified, or removed. Removed elements are drawn as ghosts in place, and the layout does not
  move. Unchanged neighbours stop at one hop: the direct caller, the store written, the state
  left. The reference says "The code is the authority; the diagrams show what changed, where,
  and with what neighbours. They never grade the change." Diagrams can be attached to a GitHub
  pull request or a GitLab merge request. The CLI runs deterministic layout-verification gates.
  Those diagram rules are on #11.
- **X.** Weak. [@EthanLinAI](https://x.com/EthanLinAI/status/2125925092970664446), 5 likes when
  read on 2026-11-26. Not re-counted here.
- **Evidence:** `vendor` + `engagement` (stars). Open source. No measured outcome.
- **Use.** #7 is the one-hop map of what the change is wired into. #11 is the diagram of the
  change, including a step a reader can attach to the pull request, and the rule that the
  diagram does not grade it. #12 is the materiality gate, a size signal (files, lines, path
  class). #15 already notes that Bisque skips a change it judges too small, so the gate is not
  repeated there.

### B. 1904 — #15 and #17

- **What.** "Pull requests from your agents now show what changed on screen", 2026-11-14
  ([news](https://1904.ai/news/pr-shows-the-screen)). `vendor`.
- **Screenshots.** For a UI change, the pull request gets a "Visual changes" comment with up to
  four screenshots the agent took while checking its work. Only screenshots of the exact
  submitted files qualify. Stale ones are dropped, and the comment says so when none match.
  Each caption names the page, the view, and the commit. Submitting again updates the same
  comment.
- **Video.** For a bigger change, captioned scenes tied to steps of a UI check become a silent
  video of at most 45 seconds. It is recorded only when checks pass on the submitted commit.
- **Evidence:** `vendor`.
- **Use.** #15 is the visual on the pull request. #17 is the commit pin: a picture from an
  older commit is dropped, and the video is tied to the commit whose checks passed. The item
  stays the interdiff of hunks and notes since the last page.

## Findings

### A. Catalan et al. — #5, #9, and #11

- **Paper.** Carlos Rafael Catalan, Lheane Marie Dizon, Patricia Nicole Monderin, Hyo Jin Do,
  and Qiaosi Wang, "Useful but Unwieldy: How Software Engineers Perceive the Design of
  Chain-of-Thought Explanations in Coding Agents."
  [arXiv 2611.30894](https://arxiv.org/abs/2611.30894). Samsung R&D Institute Philippines,
  Hanyang University ERICA, an independent researcher in Manila, and UC Berkeley. HTML is v1.
  No submission day was retrieved.
- **Study.** Survey, n=36. Semi-structured interviews, n=4. The agent in the vignettes is
  Cline, in plan mode. One vignette per person.
- **What they found.** The chain-of-thought message is valued for transparency, scrutability,
  and trust. It is too verbose, mismatched to the user's expertise, and feels "detached." P6:
  "the agent monologue-ing, like it's talking to itself." By default it is not worth reading.
  Engineers "re-attach" it when they suspect an error in the output, then scan the reasoning to
  find the cause. Participants asked for "visual links of answers back to the chain of thought"
  and "grouping of relevant contexts and reasoning." The authors propose visible links between
  the chain-of-thought content and the agent's output, building on Callisto (Wang et al., 2020,
  as cited in the paper).
- **Section 4.3.** Fewer respondents wanted visualizations for the source code (8.3%) than for
  the text, non-source-code, parts (19.4%). P6: "Adding it (visualizations) to code would just
  be bloat that needs to be removed later anyway."
- **DC1.** An up-front "getting-to-know" step. The agent asks the user's expertise and goals.
  The page also names preferred programming language. That clause stays in this note.
- **Evidence:** paper (qualitative, n=36, no controlled task measure). Not tagged
  `measured-RCT`.
- **Use.** #5. Keep decisions short and collapsed by default, link each decision to the exact
  hunk it explains, and make the log the place to jump when a reader distrusts a hunk. #9. One
  line. Expertise mismatch was a main reason the explanations were abandoned. DC1 is the
  up-front question this item already sketches. #11, not #15. Diagrams sit beside the code.
  They do not replace it. #15 already says the interactive block does not replace the page.
